# worship-edit

주일 예배 찬양 실황 멀티캠 영상을 **Final Cut Pro XML**로 받아
규칙에 따라 앵글 컷을 나누고, 악보 가사를 목소리에 맞춰 자막 타이틀로 넣은 XML을 만듭니다.

## 진행 단계
| 단계 | 내용 | 상태 |
|---|---|---|
| 1 | 엔진 + 명령어 버전 (구조 분석, 목소리 분리, 규칙 컷, 가사 싱크, 타이틀) | ✅ |
| 2 | 앱 안에서 Whisper 받아쓰기 + 가사 자동 정렬 | ✅ (가사 줄 70~85%가 ±1초 안, 나머지는 검토 화면에서) |
| 3 | 가사 보관함 (곡 제목별 가사·진행 순서 저장) | ✅ |
| 4 | Mac 앱 화면 (끌어다 놓기, 역할 확인, 검토 타임라인) + GitHub 자동 빌드 | ✅ |
| 5 | 학습 루프 (다듬은 최종본과 비교해 규칙값 갱신) | 예정 |

## Mac 앱 (4단계)
**받기**: GitHub → Releases → `latest` → `WorshipEdit-mac-arm64.zip` (Apple Silicon).
압축을 풀고 `WorshipEdit.app`을 응용 프로그램 폴더로 옮긴 뒤 **처음 한 번은 우클릭 → 열기**
(서명되지 않은 앱이라서). 그래도 막히면 터미널에서 `xattr -cr /Applications/WorshipEdit.app`.

**쓰기**
1. 파이널 컷: 컷하지 않은 멀티캠 클립 하나가 올라간 프로젝트 → 파일 → XML 내보내기 (`.fcpxmld`)
2. 앱 창에 `.fcpxmld`를 끌어다 놓기 → 앵글 역할 확인, 가사 보관함에서 부른 곡을 순서대로 고르기
   (가사 파일은 `다운로드/WorshipEdit 가사` 폴더에 두면 앱을 켤 때 자동으로 보관함에 들어감.
   ‘가사 파일 가져오기…’나 .txt를 창에 끌어다 놓아도 되고, 새 곡은 ‘새 곡…’에서 붙여 넣기)
3. 시작 → 오디오는 XML이 가리키는 **원본 녹화본에서 자동으로** 꺼냄 (외장 드라이브 연결 필요.
   못 찾으면 ‘오디오 파일 직접 넣기’로 파이널 컷에서 ⌥X 후 내보낸 오디오를 넣기)
4. 검토 화면: 타임라인(곡·멘트·컷 색·가사 위치) 확인, 빨간 ‘확인 필요’ 줄을 듣고 시간 수정, 곡 구간 수정 →
   ‘고친 내용으로 다시 만들기’ → ‘파이널 컷에서 열기’

결과는 넣은 XML 옆에 `이름_자동편집.fcpxml`(파이널 컷), `이름_자동편집_프리미어.xml` + `_가사.srt`(프리미어: 파일 → 가져오기), 중간 파일(오디오·목소리·받아쓰기)은 `이름_자동편집_작업/`에 남아서
다시 만들 때는 느린 단계를 건너뜁니다. 처음 실행 때 목소리 분리 모델(약 65MB)과 Whisper 모델(약 550MB)을
받습니다 (`~/Downloads/ggml-large-v3-turbo-q5_0.bin`이 있으면 그걸 씀).

개발용 실행: `pip install -e ".[app]"` → `worship-edit-app`

### 실황 자막(하단 가사) 읽기 — 가사 자막의 기본
실황 녹화본 화면 아래에 뜨는 예배 가사 슬라이드를 0.5초마다 문자 인식해서 **슬라이드 그대로**(두 줄, 뜬 시각·내려간 시각) 자막을 만든다.
- 맥: Apple Vision(라이브 텍스트 엔진), 개발 환경: tesseract(kor)
- 부르지 않은 슬라이드(기도·멘트 중 떠 있던 것)는 받아쓰기·목소리 소절 길이로 걸러내고, 노래가 끝난 뒤 오래 떠 있으면 노래 끝 2초 뒤에 내림
- 같은 가사가 다시 나오는지·시간 간격으로 곡을 묶음 → 가사 보관함에서 곡을 안 골라도 됨(고르면 후렴 첫 줄 규칙에 씀)
- 실황 원본을 못 찾거나 슬라이드가 거의 없으면 예전 방식(받아쓰기 + 가사 보관함 정렬)
- 읽은 결과는 작업 폴더 `실황자막.json`에 남아서 다시 만들 때는 건너뜀
- 하단 가사 위치가 바뀌면 `slides.REGION`(화면 비율 x, y, w, h)을 고친다

### 프리미어에서 시작하기
1. 프리미어: 카메라 파일 + 실황 녹화본 → 멀티 카메라 소스 시퀀스 만들기(오디오 동기화) → 클립에서 새 시퀀스
2. 타임라인에서 찬양 구간만 남기기 (앞뒤를 자르거나, 시작(I)/종료(O) 표시)
3. 파일 → 내보내기 → **Final Cut Pro XML** → 앱에 끌어다 놓기
4. 결과 `_프리미어.xml`을 프리미어에서 파일 → 가져오기, `_가사.srt`는 캡션 트랙에

실황 녹화본은 카메라 이름 규칙(C####, GH######, DJI_)에 맞지 않는 앵글 중 가장 긴 것으로 자동 인식해요.

## 준비물 (명령어 버전)
1. 컷하지 않은 멀티캠 클립 하나가 올라간 프로젝트 → 파일 → XML 내보내기 (1.14, `.fcpxmld`)
2. (선택) 같은 프로젝트 오디오 → **⌥X로 선택 구간 해제** → 공유 → 파일 내보내기 → 오디오만.
   생략하면 XML이 가리키는 원본 녹화본에서 꺼냅니다.

## 명령어 (1단계)
```bash
pip install -e .
worship-edit check  프로젝트.fcpxmld 오디오.mp3          # 길이·앵글 역할 확인
worship-edit separate 오디오.mp3 목소리.wav               # 목소리 분리 (모델 자동 다운로드)
worship-edit analyze 오디오.mp3                           # 곡·멘트 구조 추정
worship-edit build 프로젝트.fcpxmld 오디오.mp3 --vocals 목소리.wav --lyrics 가사.txt -o 결과.fcpxml
```
`가사.txt`: 한 줄에 `시간|가사[|C]` (C = 후렴 블록 첫 줄).

### 전체 자동 (2단계)
```bash
pip install -e ".[whisper]"
worship-edit lyrics add 새힘얻으리.txt          # 가사 보관함에 곡 추가 (한 번만)
worship-edit auto 프로젝트.fcpxmld [오디오.mp3] --songs "새힘얻으리, 예수 사랑하심은" -o 결과.fcpxml
```
목소리 분리 → Whisper 받아쓰기 → 가사 자동 정렬 → 곡 구조(가사로 보정) → 규칙 컷 → 타이틀까지 한 번에 합니다.
작업 폴더(`결과_작업/`)에 목소리 트랙과 받아쓰기 SRT가 남아요.

### 프리미어용으로 바꾸기
```bash
worship-edit premiere 결과.fcpxml     # → 결과_프리미어.xml + 결과_가사.srt
```
컷이 다 들어간 일반 시퀀스(멀티캠 클립 아님)와 실황 오디오가 들어가요. 4K 원본은 1080p 화면에 맞춰 크기 조절.

### 가사 보관함 파일 형식
```
제목: 새힘얻으리
진행: V V V V P C V V P P C P P P C C T T T T
후렴: C

[V]
첫째 줄
둘째 줄

[P]
...
```
`진행`은 악보 진행표 순서, `후렴`은 규칙 B 기준 파트. 한 줄 = 화면에 한 번 뜨는 자막.
가사는 저작권이 있어 저장소에 넣지 않고 사용자 Mac(`~/Library/Application Support/WorshipEdit/lyrics`)에만 둡니다.

## 컷 규칙
1. 같은 앵글 연속 금지 · 2. 인도자가 가장 많이 (카메라 2대 62%, 3대 45%, 4대 이상 35%) · 3. 조용한 구간 드럼 금지
4. 곡 시작: 드럼 카운트 → 드럼, 건반 인트로 → 피아노 · 5. 드럼 예비박 뒤 첫 간주 → 기타
A. 멘트·기도 인도자 고정 · B. 후렴 첫 소절 인도자/싱어 · C. 마지막 후렴 컷 20% 짧게 · D. 곡 끝 8초 인도자

## 자막 스타일
Basic Title · NanumMyeongjo 50 · Position 0 -450 · Face 흰색 100% / Blur 0 · Outline 검정 20% / 0.5 (XML에는 strokeWidth -0.5: 음수여야 면이 채워짐) · Drop Shadow 검정 75% / Blur 7.53 / Distance 5 / 315°

## 앵글 역할 자동 분류
`C9xxx` 인도자 · `C1xxx~C8xxx` 싱어 · `DJI` 두 대 중 번호가 작은 쪽 드럼, 큰 쪽 피아노 · `GHxx` 기타 · `YYYY-MM-DD HH-MM-SS` 실황 녹화본(오디오)
